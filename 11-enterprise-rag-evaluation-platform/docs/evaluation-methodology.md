# Evaluation methodology

## Dataset and provenance

`examples/evaluation-fixture.json` is generated by `scripts/build-dataset.mjs`: 17 synthetic documents and 33 authored cases in English/Persian. Labels are not independently human-reviewed. This is a regression/development set, not a held-out effectiveness benchmark. Thresholds and the coverage gate were chosen while inspecting these cases; perfect outcomes are therefore not evidence of generalization. Before externally claiming superiority, freeze a separate independently reviewed holdout and report its results unchanged.

## Metrics

| Metric | Exact definition | Applicability |
|---|---|---|
| Precision@K | Relevant unique retrieved IDs / configured K | Cases with gold documents |
| Recall@K | Retrieved gold IDs / total gold IDs | Cases with gold documents |
| MRR | Reciprocal position of first gold document | Cases with gold documents |
| nDCG@K | Binary DCG / ideal binary DCG at K | Cases with gold documents |
| Quote support | Fraction of claims that exactly match a complete sentence in a cited retrieved source | Cases containing claims |
| Citation precision | Exact-sentence-supporting citations / all submitted citations | Cases containing claims |
| Fact coverage | Expected fact IDs whose corpus-owned text exactly matches a supported claim / expected fact count | Cases with expected facts |
| Outcome accuracy | Observed action matches expected answer/abstain/review/block | All cases |

Macro averages across applicable cases are reported with denominators. No-answer retrieval is null, not 100%. Scores stay full precision for gates; rounding is display-only. Fact coverage is a recall-like quantity, not complete answer correctness. An answer can quote irrelevant but true source sentences; retrieval precision helps expose that, but answer relevance is not separately modeled.

## Safety and uncertainty

Known-pattern injection scanning is a limited heuristic, not a comprehensive security detector. Expected blocks count as correct outcomes; unexpected blocks independently fail policy. Conflicting retrieved topic/value metadata results in review. Missing retrieval produces abstention. Paraphrases and altered numbers fail exact-quote checks; a failed quote check does not prove that a paraphrase is factually false.

## Baselines, slices and ablations

Dataset, policy and engine hashes must match. Per-metric deltas and quality/slice gates jointly control the result. A passed result is eligible for human review. The baseline is a reference execution, not necessarily a previously approved release. No evidence of human release approval is implied by selecting it.

Ablations compare lexical K=1, BM25 K=1, BM25 K=2, and BM25 K=2 plus phrase reranking. Phrase reranking adds a deterministic bigram bonus to the top ten candidates. `minQueryCoverage` prunes lexical/BM25 documents below a fraction of query-token matches; it is illustrative, language-dependent and does not apply to embedding cosine scores.

Paired percentile bootstrap uses the same case IDs, seed 42 and 600 resamples for outcome-accuracy delta. Cases sharing documents are correlated and slices are small; the interval is descriptive and not proof of general superiority. No universal threshold or production latency claim is made.

## Optional semantic judge

A configured local model can label claims supported/unsupported/uncertain against cited text. These are advisory model opinions. Calibration accepts independently human-labeled rows, reports false-support rate, precision and coverage, and records reviewer declarations. The application cannot independently authenticate those human declarations. No human calibration data is bundled or fabricated. Judge scores never grant release approval.
