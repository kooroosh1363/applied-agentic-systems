# Definition of Done

A project is complete only when:

- behavior and acceptance criteria are documented;
- imports, source files, schemas, and examples parse successfully;
- deterministic tests cover the critical path and defined failures;
- retries, duplicates, timeouts, and invalid inputs have explicit behavior;
- secrets and personal data are absent;
- architecture, data flow, threat model, limitations, cost, and KPI are documented;
- monitoring signals identify success, failure, retry, and DLQ activity;
- local setup does not require a paid service;
- CI passes from a clean checkout;
- the pull request distinguishes tested facts from future production work.
